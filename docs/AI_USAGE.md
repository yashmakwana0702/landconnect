# AI tools usage

## Tools

| Tool | Used for |
|---|---|
| **Claude Code** (Anthropic CLI agent, Claude Opus 5.5 model) | Main pair-programmer: planning, scaffolding, writing backend and mobile code, tests, debugging, docs |
| **Context7 docs lookup + Expo `llms.txt`** (through Claude Code) | Checking current APIs for Expo SDK 58, Expo Router, image picker, location, EAS and the LiveKit React Native SDK, instead of relying on model memory |
| **Claude API** (inside the product) | Optional: turns a buyer's free-text requirement into structured search filters (`backend/app/services/matching/extractor.py`) |

## How the work was split

**My decisions** (given to the agent as constraints):
- Priority order: calls first, then auth and roles, then listings with maps, then chat, then the AI extra only if time allowed.
- Stack: Expo + TypeScript; FastAPI + PostgreSQL with thin routers, services, Pydantic models and async I/O.
- A managed WebRTC SDK rather than raw WebRTC.
- Keep it a prototype and skip anything outside the spec.

**What the AI did**, iterating in the terminal:
- Proposed the architecture: LiveKit for media, our own WebSocket signaling, and a call state machine in Postgres.
- Wrote the FastAPI services and tests, and the Alembic migration (autogenerated against a local Postgres).
- Wrote the Expo screens and the LiveKit call UI.
- Ran the checks listed below and fixed what they found.

**Things the AI got wrong and fixed after feedback from tools:**
- A PowerShell bulk-replace script corrupted five TypeScript files; they were restored and re-checked.
- `react-native-webview` typings collapse to `never` under TypeScript 6; this needed a typed wrapper.
- React Compiler lint rules flagged ref writes during render and setState calls in effects; these were refactored, not suppressed.
- `expo-doctor` caught a missing `expo-font` peer dependency.
- Python packages were leaking in from the user site-packages directory; the conda env was isolated.

## How the output was verified

- `pytest`: 23 backend tests covering auth, role permissions, the privacy of phone/email, listing CRUD, images, location blurring, chat delivery, meeting rooms, and every call transition (accept, reject, cancel, busy, calls disabled, outsider, group, timeout to missed). No network calls; the realtime bus is faked.
- An end-to-end script against the real API on Postgres: login → chat → call with the callee listening on a real WebSocket → accept → end → call-log message → AI match.
- A **real LiveKit server** test: two LiveKit clients joined with tokens issued by `/calls` and `/calls/{id}/accept`, landed in the same room, and each saw the other (including the published audio track).
- Mobile: `tsc --noEmit`, `expo lint`, `expo-doctor` (20/20), and an Android bundle export, all clean.

## Where AI helps inside the product

The matching feature uses the LLM only where it adds value: reading messy human input ("2.5 cr", "5-10 acres", "near Hoskote", "clear title"). Ranking is deterministic, weighted and explained, so a buyer can see why a parcel was suggested. If the model is unavailable, a rule-based parser keeps the feature working.
